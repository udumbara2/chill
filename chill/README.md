# chill

一个 AI 助手 = 一个会话引擎（ChatEngine）+ 两种壳。对话、Subagent 委派、MCP、Skill、长期记忆、规划模式，全部能力两端一致。

## 两条独立安装路径

### 只装 CLI（终端）

```bash
npm install -g @assistant-ai/chill-cli
chill
```

- 无需克隆仓库、无需桌面端；CLI 进程不加载任何 UI/Vue/Electron 代码
- 对话、`task` 委派（含并行与按任务性质指定模型）、MCP、Skill、记忆、规划模式全部可用
- 详见 [packages/cli/README.md](packages/cli/README.md)

### 只装桌面窗口（全档）

```bash
npm install -g @assistant-ai/chill
```

用法与轻档完全一致（同一个 `chill` 命令），另有独立 Electron 桌面窗口：TUI 内 `/ui` 启动并**接力当前会话**（终端聊到一半，窗口里接着聊）。安装多拉约 100MB Electron 运行时（国内建议先设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`）。可视化工作流与写作视图、任务栏闪烁提醒（回答完成时窗口未聚焦/已最小化，点回窗口自动停止）都在窗口内。

**两条命令不要同装**（`chill` 命令名冲突，npm 报 EEXIST；卸一个即可）。

### 两者都装（并存场景）

CLI 与桌面窗口各自独立运行，**共享同一份 `~/.chill/`**（API Key、模型配置、会话、记忆、Skill、MCP 配置）：

- 一端建立的会话可在另一端继续（`~/.chill/sessions/`，跨端 watch 实时同步）
- 会话前台选择（裸模型 / 本地 Agent）随会话持久化，跨端续聊保持一致

## 基本使用

```bash
chill                  # 交互式对话
chill -p "任务"        # 非交互一次性执行（默认只读）
chill -p --auto "任务"  # 非交互一次性执行（放开修改）
```

- `/help` 全部命令；`/model` 选模型；`/front` 选会话前台；`/plan` 规划模式；`/compact` 压缩上下文；`/session` 会话管理；`/tasks` 后台任务列表；`/add-dir` 扩展可写目录；`/improve` 改进提案决策（助手自动从会话攒改进提案，按问题簇整组裁决，`/improve review` 深度审查）；`/idea 一句话` 记闪念点子（入改进提案「闪念」簇；流式输出中也可用；手机端首屏 💡 / 长按 ＋ / ☰ 维护节同源；仅自迭代模式可用，npm 模式入口不存在）
- `@` 是统一提及语法：`@<文件路径>` 提及文件（发送图片或视频，多模态模型）；`@<subagent_type>` 提及 agent（点名委派，见下节）；`Ctrl+X` 中断生成
- 委派无需切换模式：模型经 `task` 工具直接委派 Subagent，可按任务性质指定模型，进度实时呈现

## 写边界(圈内直接写,圈外当场审批)

chill 的写权限模型是**路径级边界**:安全来自边界而非审批。

- **圈内直接写**:默认只能直接写**边界目录**内的文件——边界 = 会话工作目录(CLI 启动目录 / 桌面 UI 写作视图打开的文件夹)+ `/add-dir` 加入的目录(本次会话有效)。圈内写不弹窗、直接落盘,前台对话与后台 subagent 一致
- **圈外当场审批**:写边界外的路径时,该次写就地暂停并弹出审批(diff 预览 + 归属"后台任务 X 请求…/主对话请求…"),三个选择:`[y]` 只批准这一次、`[d]` 批准并把写目标所在目录加入本次会话、`[n]` 拒绝
- **`/add-dir <路径>`**:把项目目录加入本次会话可写范围(在项目目录里启动 chill 则天然圈内);`/add-dir` 无参列出当前边界
- **AI 知道圈在哪**:每轮注入当前可写范围,AI 会自觉落在圈内,写圈外前会提前说明
- **权限三态**:执行权限分只读/边界/直写三档——只读 = 修改性工具全部拦截;边界(默认) = 圈内直接写 + 圈外当场审批(对齐 Codex workspace-write);直写 = 任意路径直接写不问(仅建议信任场景/隔离环境,危险命令仍审批)。CLI 用 `/auto-apply on|off`(on=直写、off=边界),桌面 UI 提供三态选择器
- **命令执行**:`execute_powershell` 维持 off=即时询问(带归属)/on=直通(危险命令除外,永远审批);`execute_code`(JS/Python 本地执行,代码写临时文件直调解释器、不经 shell 解析)走同一审批链
- **其他保护**:chill 自身源码树(workcopy 外)禁写不变;升级前会话历史中的"已暂存操作"PENDING 占位为显示残留(功能无影响)

## 备份与回滚(/restore)

文件编辑工具(create_file/insert_content/replace_content/delete_content/autoApply 批次,含后台委派写)每次落盘前,自动把写前内容留存为快照——**可逆是写权限模型的最后一层**。

- **存哪**:`~/.chill/backups/`(与工作目录零干扰,CLI 与桌面 UI 共享同一份,一端写的另一端可恢复)
- **存多久**:每文件最多 10 份 + 7 天自动清理,先到为准
- **文件级恢复**:CLI `/restore <文件>`(编号选择,旧版散落的 `.backup-*` 仍只读兼容);桌面 UI 文件树右键「恢复备份」(按文件/按轮次双视图 + diff 预览)
- **轮次级回滚**:CLI `/restore` 无参,列出本会话最近 10 轮写入(含后台任务组),选中一键把整轮涉及的文件全部恢复到写前状态
- **回滚可再回滚**:恢复前会自动给当前内容再拍一份快照;恢复后 AI 会收到留痕通知,不会按旧认知继续改
- **撤销创建**:AI 新建的文件恢复到"创建前状态"= 文件移入回收站
- **边界(如实声明)**:删除走系统回收站(不留快照);`execute_powershell`/`execute_code`/hooks 造成的改动不在快照内(防线是命令审批+git);单文件超 10MB 不留;`.env`/`*.key`/`*.pem`/`id_rsa*` 等敏感文件不留(避免凭证明文副本)

## 工具渐进发现（/tools）

内置工具较多,默认只常驻下发核心工具;模型需要更多能力时会自行调用 `search_tools` 检索并激活(下一轮起可直接调用),Token 占用随之下降。

- `/tools`(同 `/tools status`)查看当前下发状态与类别分布;`/tools mode off` 退回全量下发,`/tools mode on` 恢复
- 开关存 `progressive_tools` 配置键,默认开启;可延迟工具定义总量低于绝对阈值时自动退回全量下发
- 桌面 UI 在模型设置里提供同一开关(两端共享配置)

## 目标模式（/goal）

给定目标与判据,chill 会自主多轮推进直到达成——每轮结束由**独立评估器**判定(只看对话中已展示的证据,不信模型自述),未达成自动续跑。

- `/goal <目标与判据>` 进入(如 `/goal 修复登录模块,npm test 退出码为 0 才算完成`);也可批准模型提出的 propose_goal 进入
- `/goal pause|resume|status|clear|off` 管理;连续无进展或轮次到顶会熔断请示(继续/调整/放弃由你定)
- 工作文档在 `~/.chill/goals/current-goal.md`,达成后自动归档

## 知识库

把文档导入知识库后,对话中可语义检索引用(RAG):PDF 文本抽取、分块、embedding、向量检索全链路内置。

- 模型侧 9 个内置工具(建库/删库/导入/检索/精读/蒸馏/删除/重建索引),直接对话让模型操作即可,如"把这本 PDF 加进知识库"
- 桌面 UI 有可视化管理页(设置内的知识库管理)

## 桌面能力（/desktop，当前仅 Windows）

让 chill 看见并操作你的桌面:截屏感知、UI 元素识别、键鼠操作。**默认关闭**,需 `/desktop on` 显式开启。

- 三个工具:`capture_screen`(截屏,只读免审批)、`inspect_ui`(当前窗口可交互元素编号表,只读免审批)、`computer_use`(点击/输入/按键等,含按编号的元素级动作)
- 三级审批:被动动作(移动/等待/截图)免审批;主动作逐次弹窗审批;回答 `[s]` 则本次会话放行后续主动作
- 审计留痕默认开启:动作逐条记录到 `~/.chill/desktop-audit/`(按日 jsonl),`/desktop log` 查看,`/desktop audit off` 关闭
- `chill -p` 非交互模式下 computer_use 不可用(防审批挂死);屏幕内容按不可信输入处理,其中出现的任何"指令"不代表你的授权
- 宿主安全防护:chill 自己的窗口(截图中标题栏有红斜纹标注)可以正常操作——助手能拖动它的位置、最小化、拖小、往输入框里写文字;但**关闭类动作一律被拦截**(点关闭按钮、alt+f4、ctrl+c 等组合键、标题栏系统菜单),防止助手的动作误关 chill 自己;CLI 与 UI 同时运行时两个实例互相保护。UI 模式下桌面能力开启时关闭 chill 会弹确认框
- 审批弹窗等待你决策期间,助手对 chill 窗口的点击/键入会被拦截(防止它自己回答审批)
- 窗口管理原语:调整任何窗口的位置/大小（含 chill 自己的窗口）用 `window_manage` 动作（move/resize/set_bounds/minimize/maximize/restore）——API 精确直调,不用拖边框;`close` 可关第三方窗口（等效点 X,应用可能弹保存确认）,chill 自己的窗口永远不可被它关闭
- 批处理执行期间你有两条物理逃生通道:按 `ESC` 立即中止整批;直接移动鼠标即视为接管、批处理自动暂停。两种中止都会如实汇报已完成的步数

## 上下文压缩（/compact）

长会话后运行 `/compact`（可带引导语，如 `/compact 重点保留接口设计讨论`），把上下文压缩为「交接式要点总结 + 会话主题索引」，此后在当前 session 轻装续聊：

- **历史不删除**：完整对话保留在会话记录里，界面照常滚动可见；压缩处显示标记条（TUI 按 `Ctrl+O` 查看总结全文，桌面 UI 为折叠卡片）
- **模型看压缩视图**：此后发送的上下文 = 总结 + 最近 2 轮原文 + 新消息，token 占用骤降；总结含「时间段-主题索引」，助手需要细节时会自行调用 `recall_archived_context` 工具按主题或时间段取回原文
- **多次压缩**：每次生成一条 checkpoint 追加到同一会话记录（不新增会话文件），新总结承接旧总结
- **边界**：有后台任务在跑时拒绝压缩；撤销压缩 = 删除会话记录中对应 checkpoint；需两端（CLI/桌面 UI）同版本

## 委派异步化(后台任务)

委派默认**后台执行**:AI 派出任务后立即可以继续对话,不阻塞;同批任务全部完成后 AI 自动整合结果向你汇报。

- **进度与查询**:任务开始/完成有轻提示;随时可问"现在有哪些任务在跑",或用 `/tasks` 命令列出运行中与近期任务
- **取消**:让 AI 取消某个任务(cancel_task),Worker 进程会被真正销毁;`Ctrl+X` 只打断当前对话轮,不杀后台任务
- **同批语义**:一次派多个任务时,等同批全部完成才合并汇报一次;不同批次互不等待;单个任务完成即报
- **结果保真**:Subagent 的最终报告**完整回传**,平台不做摘要截断;单个结果超 400KB 时全文落盘 `~/.chill/task-results/`,回执带文件路径与预览,AI 需要细节时自行 read_file 取回。报告被输出配额(maxTokens)剪断时尾部带【警告】标记,可用 `override_parameters.max_tokens` 调大重派
- **写入与审批**:后台任务写文件走与主会话相同的写边界——圈内直接落盘,圈外当场弹出审批(带归属)
- **会话护栏(按壳形态分述)**:交互 CLI 是单引擎壳——有后台任务在跑时不能切换/新建会话(防止结果回流到错误的会话),完成或取消后即可。桌面 UI 与 `chill serve`(手机遥控宿主)是多会话壳——每会话独立引擎,切换=切指针,**运行中的会话切走后台续跑**;会话自己的后台任务在跑时该会话不能压缩/重载,但**不阻塞其他会话的任何操作**(任务按引擎句柄归因,跨会话无因果)
- **`chill -p` 维持同步**:非交互模式行为不变(跑完才退出)
- 边界:任务是进程内的,进程退出即终止(重启后历史里的"后台进行中"会标记为已中断);同一时刻多进程操作同一会话的后台任务为不支持场景

## 自定义 Agent 模板

写一个 Markdown 文件即可创建自己的 agent（Subagent 模板），保存即生效、无需重启：

- **个人级** `~/.chill/agents/templates/*.md`：所有项目可用
- **项目级** `<项目>/.agents/agents/*.md`：随 git 仓库共享，仅当前项目（从工作目录向上递归各级）生效；同名时 **项目级 > 个人级 > 内置**

```markdown
---
name: 安全审查员
subagent_type: security-reviewer
description: 只读安全审查,专查注入、越权、密钥泄露
model: 某模型名        # 可选;不写则跟随当前会话模型
tools: [read_file, grep]  # 可选;不写则委派时按任务分配
---
你是一名安全工程师,只读不改。按严重级别输出发现,每条附文件与行号、修复建议。
```

- `name` 与 `subagent_type` 必填（`subagent_type` 规则：小写字母/数字/连字符）；`description` 决定委派时能否被正确选中，务必写清"什么时候该用它"
- 委派时模型优先级：委派动态指定 > 模板 `model` > 当前会话模型
- 与 AGENTS.md 的分工：常设约束（构建命令、代码风格、全员纪律）写 `AGENTS.md`；角色定义（专职能力、专用模型/工具）写模板
- 生效时机：CLI 对两级目录均有文件监听，改动下轮对话生效；桌面 UI 个人级热生效，项目级在会话打开/切换工作目录时加载。运行中新建 `.agents/agents/` 目录需重启后生效
- 项目级模板随仓库分发，引入他人模板前请留意内容（模板含工具授权与指令）

### @ 提及 agent（直聊 / 委派双通道）

`@<subagent_type>` 是 agent 的统一入口，按内容自动分意：

```
@security-reviewer                  # 裸提及：切换为与该 agent 直接对话（前台直聊）
@security-reviewer 审查一下最近的改动  # 带内容：点名委派（后台执行，完成自动汇报）
@图.png @code-reviewer 审查这张图     # 文件提及与 agent 提及可同用
```

- **裸提及 = 直聊**：只喊名字即切换前台——之后每句话直接由该 agent 应答（它的角色、模型、工具面），主模型不经手；切换瞬间完成，不发起模型调用。`/front off` 恢复裸模型，或裸 @另一个 agent 直接换聊；也可用 `/front` 命令或 UI 左下角前台选择器切换。远程模板只能委派，裸 @ 会提示
- **带内容 = 委派**：把这条任务点名委派给该 agent（后台执行，见上节"委派异步化"）
- **直聊时的模型**：模板写了 `model` 就用模板的（状态栏标注"模板指定"），没写跟随你当前选定的模型；直聊时模板 `tools` 白名单同样生效（只读模板直聊也只读）
- 规则：**精确匹配**模板 `subagent_type` 才触发，不匹配按普通文本；一条消息有多个 @agent 时**取第一个**
- TUI 与桌面 UI 输入 `@` 会弹出 agent 选择列表（含内置/个人/项目模板），点选自动补全
- `chill -p` 非交互支持带内容委派，但默认只读档会拦截 `task`，需 `chill -p --auto`
- 规划模式（/plan）下可委派**只读**任务（Subagent 只获得只读工具）；不可委派修改操作

## 生命周期 hooks（说一句话就有的确定性护栏）

hooks 是在 chill 运行链路的确定性点位上执行你自定义脚本的机制：**说一句话，chill 就自动生成脚本并把逻辑确定性钉进链路**——不写代码、不懂协议也能用。

- **自然语言创建**：直接对 chill 说（或用 `/hooks add <描述>`），例如"每次写完文件帮我跑一遍 eslint --fix""不许执行 rm -rf 开头的命令""npm test 以后别问我了"。chill 自动生成单文件脚本 + 配置条目，安装前展示脚本全文、挂载事件与匹配规则，你确认才生效；改和删同样对话式
- **典型场景**：安全护栏（拦截危险命令并把原因反馈给模型换方案）、白名单免审批（只读命令自动批准不再弹窗）、自动格式化/检查（写完代码自动跑 prettier/tsc，失败信息回灌模型当场自修）、会话开场注入（git 状态/TODO 自动进上下文）、完成前跑测试（不过则强制继续干）、目标达成/熔断时通知你
- **`/hooks` 命令**：`/hooks list` 查看已配置 hook（事件/matcher/命令/启用状态/来源/信任状态）；`/hooks enable|disable <id>` 启停；`/hooks log` 查最近 50 次触发记录（事件/耗时/exit code/决策），排障第一站
- **配置位置**：用户级 `~/.chill/hooks.json`（所有项目生效，两端共享）；项目级 `<项目>/.agents/hooks.json`（随 git 仓库分发，clone 即用，同名项目级优先）。改配置下一轮对话即生效
- **生态兼容**：事件名、stdin/stdout 协议、exit code 语义对齐 Claude Code 事实标准，并提供 `CLAUDE_PROJECT_DIR` 兼容别名——社区现成 hook 脚本改个路径即可在 chill 上跑
- **安全说明**：项目级 hooks 首次出现或内容变更时需当场信任批准，批准前不执行；hook 超时或脚本崩溃默认 fail-open（只警告不卡死对话）；hook 进程以你的凭据执行、不受写边界约束，安装确认时看清脚本内容再批准

## 定时任务（说一句话，chill 到点自动做）

定时任务让 chill 在指定时刻自动执行一轮任务：到点后任务指令作为一条消息注入会话自动跑一轮，结果就在对话上下文里、可直接追问——不写 cron、不用开第二个终端、不用守着。

- **典型场景**：一次性提醒（"20 分钟后提醒我起来活动"，触发后自动完结）；每日例行（"每天早上 9 点汇总昨天的 git 进展"）；周期巡检（"每周五下午 5 点检查一遍项目依赖更新"）；看护跟进（"每 10 分钟看一下流水线状态，好了告诉我"——看护任务条件达成时可自动取消自身）
- **自然语言创建**：直接对 chill 说需求即可，模型经内置工具 `schedule_task` 起草调度方式与任务指令，创建前展示调度规则、prompt、下次触发时刻与归属范围，你确认才生效；改和停同样对话式
- **管理**：`/schedule list` 查看全部任务（id/调度/prompt/归属/下次触发/状态），`/schedule cancel <id>` 取消；对话中说"我现在有哪些定时任务"也可经 `list_scheduled_tasks` 查询、经 `cancel_scheduled_task` 取消（取消需审批）
- **调度语义**：周期任务用 5 段 cron（分 时 日 月 周，本地时区；整点类任务自带几分钟确定性抖动，防多任务扎堆同一秒）；一次性任务可直接说相对时间（"20m"/"2 小时"），无需自己算时刻。任务默认绑**项目**（该项目任意会话到点都会触发），看护跟进类才绑具体会话；任务默认长期有效，短期看护可设截止时间（"盯到周五就停"）
- **关了再开不丢**：chill 关闭期间错过的触发，下次回到该项目会话时**合并补跑一次**（信封标注错过次数），不会一觉醒来连跑多轮
- **权限边界**：定时回合沿用会话既有权限门——你不在场时修改性工具被只读门/审批拦住，等你回来再批；看护任务在定时回合内取消自身免审批（"好了就停"的闭环）
- **执行前提**：至少一个 chill 进程在线——**`chill serve on` 常驻宿主 7×24 持钟**（手机遥控场景人不在电脑前也按时执行；serve 与你开着的 CLI/桌面 UI 并存时跨进程互斥，同一任务不会双跑）；无任何进程在线时不能唤醒机器，错过的一律靠"再开时合并补跑"兜底；最小粒度 1 分钟，不支持秒级
- **归属**：在哪个会话创建就归谁——"20 分钟后提醒我"回**这个会话**（session 类）；项目例行公事绑**项目目录**（project 类），到点注入该项目下最合适的会话（无则在 serve/UI 上新建承接会话，结果可查）；绑定的会话被删除后任务如实转「归属会话已删除，不再触发」

## 自迭代（修改 chill 自身）

CLI 内 `/fetch-source` 下载源码到 `~/.chill/workspace/` 并构建，随后可让 chill 修改自身源码
（workcopy 内变更，`/switch-version` 切换、`/discard-version` 放弃；`/use-self` / `/use-npm` 双向切换）。

## 开发（monorepo）

本仓是四件套容器仓（chill / chill-guardian / chill-relay / chill-mobile），monorepo 在 `chill/` 子目录：

```bash
git clone https://github.com/udumbara2/chill.git
cd chill/chill
pnpm install
pnpm build          # core + 渲染层 + electron 主进程
pnpm build:cli      # CLI esbuild 三入口 bundle
pnpm electron:dev   # UI 开发模式
pnpm electron:build # 打桌面安装包（dist-electron/）
```

包结构：`packages/core`（唯一引擎与全部能力）、`packages/cli`（终端壳）、`packages/ui` + `packages/electron`（桌面壳）。

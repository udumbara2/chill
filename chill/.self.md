# chill 项目结构

## Monorepo 包结构（6 个包）

```
chill/
├── packages/
│   ├── core/        ← 唯一引擎（ChatEngine）与全部能力，平台无关
│   ├── cli/         ← 终端壳（npm 包名 @assistant-ai/chill-cli，bin chill）
│   ├── ui/          ← Vue 3 渲染层（桌面与 Web 共用；HostAPI 契约类型唯一事实点在本包 src/host/）
│   ├── electron/    ← Electron 桌面壳
│   ├── web/         ← Web 宿主 daemon（chill web：静态服务 + HostAPI over WS + 能力网关，无视图）
│   └── native-desktop/ ← Rust 原生模块（napi-rs：截屏 xcap + 键鼠 enigo）；core 不直接依赖，宿主经 IDesktopController 注入（约定见 IDesktopController 接口与各宿主适配器）
```

架构一句话：**一个 AI 助手 = 一个会话引擎 + 四种壳**（CLI/桌面 UI/Web UI/手机端 chill-mobile——Web UI 经 `chill web` daemon 以 HostAPI over WS 复用 ui 渲染层；手机端经盲中继与桌面互通，修改手机端走 mobile-iterate 技能）。对话、委派、标题、确认写回、持久化、planMode/goalMode 全部只有 core 一份实现；壳只渲染与回传用户决定。

## 依赖关系

```
@assistant-ai/chill-cli (cli) ──→ @assistant-ai/core（打包期内联，运行时无依赖）  ← 直接使用 core
@assistant-ai/ui ──→ @assistant-ai/core                            ← 通过 Electron IPC 桥接
@assistant-ai/electron                                             ← 桌面壳，桥接 ui 和 core
@assistant-ai/web ──→ @assistant-ai/core                            ← Web 宿主 daemon（Node 进程直接装配 core；Web 前端复用 ui 渲染层）
@assistant-ai/native-desktop                                       ← Rust 原生模块，cli/electron 主进程经 IDesktopController 注入使用（core 不依赖）
```

- core 是唯一引擎与全部能力（双入口：Node 全量 / renderer 纯逻辑），不依赖任何平台
- cli 在 Node.js 环境运行，提供适配器实现（esbuild bundle 后独立分发）
- ui + electron 在桌面环境运行，通过 IPC 提供适配器实现
- web 在 Node.js 环境运行，daemon 直接装配 core 实例（能力网关包 core 服务），前端与桌面共用 ui 渲染层
- 包边界（T7 固化）：core/cli 不 import ui/electron，ui/electron 不 import cli；web daemon 只依赖 core（不 import cli/ui/electron）；cli→web 仅为构建产物拷贝 + `chill web` lazy 派发（web 不在时零 web 产物加载）；Web 前端复用 ui 渲染层属架构原则 4 的「WebUI 与 UI 共用代码」另行约定项；宿主专属能力一律经注入器/适配器进入引擎

## 构建系统

- pnpm monorepo 管理
- native-desktop 使用 napi-rs（`napi build --release --platform`，根 build 链最前执行）：产出 `*.win32-x64-msvc.node` + index.js/index.d.ts（包根，进版本快照——快照在无 Rust 环境可运行）；`target/`（Rust 构建缓存，~1.5GB）不进入任何拷贝载荷——self-iterate skill 第四步（chill→workcopy）、switcher 步骤3（workcopy→版本目录）、freeze.js（chill→版本目录）三处 robocopy 均以 `/XD target` 排除（robocopy 默认会遍历 junction 实化缓存，排除是正确性要求，switcher 步骤3后有防漂移守卫）；缓存全局一份：项目父目录 `chill-rust-target/` 共享，workcopy 与当前 chill 版本内的 `target` 均为指向它的 junction（skill 第四步半创建），cargo 增量语义与拷贝携带时一致；cli/electron 打包均将其列为 external，运行时 createRequire 加载
- core 使用 tsc -b（项目引用模式），同时输出 ESM（dist/）和 CJS（dist/cjs/）
- cli 使用 esbuild（`scripts/build.mjs`，dev 可 `--watch` 增量）：三入口 `dist/bootstrap.js`（薄启动器小入口）、`dist/cli.js`（主 bundle，core 全量内联）、`dist/workers/GenericSubagentWorker.js`（自包含 worker），复制 templates/skills/guardian；**cli.js 入口启用 `splitting: true`——TUI 壳（ink/react/tui/）经动态 import 进入懒加载 chunk（如 dist/TuiApp-*.js），纯 CLI / -p / 非 TTY 不加载不解析**；external 含 `react-devtools-core`（ink 仅 DEV=true 时动态加载）；打包前 `tsc --noEmit -p` 类型检查。三处 bundle（cli/electron/worker）均配置 `alias: node-fetch → core/src/shims/nativeFetch.ts`：openai@4 的 node shim 静态依赖 node-fetch v2，打平后启动即报 punycode DEP0040/url.parse DEP0169，整体替换为原生 fetch 替身后消除；core 的 OpenAI 客户端同时显式传 `fetch: globalThis.fetch`
- ui 使用 Vite 打包（`build:renderer` 在 vite build 前先跑 `scripts/clean-dist.cjs` 清空 `packages/dist`，防带哈希的旧 bundle 累积——曾达 34 个 bundle / 75M 并被固化进每个 chill-versions 版本。注：本机工作区路径含中文，Node 24 的 `fs.rmSync(recursive)` 在此路径下静默失败，故 vite `emptyOutDir` 不可靠，清空由手工遍历的 clean-dist.cjs 保证）；多页入口 index.html（桌面）+ web.html（Web 壳）
- web 使用 esbuild（`scripts/build.mjs`）：daemon bundle（dist/serve.js）+ GenericSubagentWorker bundle；cli 构建把 web daemon 与前端资产拷进 `dist/web/`（bootstrap 据此 lazy 派发 `chill web`）；验收两件套 `scripts/browser-check.mjs`（CDP 无头）与 `tests/contract.test.ts`（node:test，14 项）
- electron 使用 tsc --noEmit + esbuild（electron-main/preload，CJS）+ `scripts/build-worker.mjs`（worker 自包含 bundle 到 resources/workers）；electron-builder 打 nsis/dmg/AppImage（electronVersion/electronDist 钉本地，国内网络需 `ELECTRON_BUILDER_BINARIES_MIRROR` 环境变量）

## CLI 命令

命令行工具名 `chill`，启动后处于默认对话路径（`> ` 提示符），直接输入文本即可对话。对话统一走 ChatEngine：模型可经 `task` 工具委派 Subagent（可并行、可按任务性质指定模型），无需切换模式。壳模式 auto/mcp/workflow 仅区分提示符与管理面。

### 壳模式

| 模式 | 提示符 | 用途 |
|------|--------|------|
| auto（默认） | `> ` | 自由对话，直接输入文本与 AI 交互 |
| MCP | `mcp> ` | MCP 服务端管理（connect、disconnect、list、tools） |
| Workflow | `workflow> ` | 工作流管理（list、run） |

用 `/mcp`、`/workflow` 进入对应模式，`/back` 返回 auto 模式。

### 自迭代相关命令

- `/auto-apply on`：自迭代前建议开启，否则每个 PowerShell 命令都需要手动确认
- `/auto-switch on`：自迭代成功后自动切换版本（触发 guardian）；关闭时打开体验窗口，需手动 `/switch-version`
- `/switch-version`：检测到 `.ready-for-switch` 后启动 guardian 执行版本替换
- `/discard-version`：删除 `chill-workcopy` 目录（危险命令，需确认）

## 版本切换机制（Shadow Copy + junction）

> **当前布局状态（2026-07-24 恢复）**:junction 曾因复制粘贴失效,引擎化重构一度直接在真实 chill 目录内完成;当日已恢复标准布局——重构成果固化为 `chill-versions/v20260724-095046/`(当前版本),junction `chill` 重新指向它,`chill-versions/v20260720-233209` 为回滚目标(previousPath),`current.json` 已校正。以下为机制设计文档。

- `chill` 是 junction，指向 `chill-versions/v<时间戳>/` 下的真实版本目录（首次切换时真实 chill 目录自动迁移为 `v-legacy-<时间戳>/`）
- `chill-guardian/switcher.js` 为版本管理器：robocopy 复制 workcopy → 新版本目录 → pnpm install → 切换 junction → 清理 workcopy；`--rollback <chill路径> [版本]` 回滚到指定版本（缺省依据 `chill-versions/current.json` 拨回上一版本）；`--delete <chill路径> <版本>` 删除指定历史版本（当前版本与 previousPath 拒删，删后复查防静默失败）；`--launch <chill路径>` 启动新版本窗口。CLI 内 `/rollback` 交互选择版本、`/r <版本>` 直接回滚、`/delete-version <版本>` 删除历史版本
- 切换调用（trigger_guardian / /switch-version / /r）**同步等待** switcher 完成并解析其 `RESULT_JSON` 输出：成功 → 立即 `--launch` 开新窗（trigger 路径由旧 CLI 在模型告别完毕后自行退出；手动路径 10 秒后退出）；失败 → 诊断（rename 失败鉴别：EBUSY=占用锁；EPERM+删除允许=策略锁[DLP/OneDrive 钉住]）写入 `chill-guardian/switch-failure.json` 并回传给模型/用户，CLI 不退出，可处理后重试
- 切换只操作 junction（创建/删除/重命名链接），不重命名正在使用的目录，与体验窗口、终端 CWD 状态无关
- **版本固化用 `chill-guardian/freeze.js`**（`node chill-guardian/freeze.js`，`--dry-run` 只复制校验）：robocopy 固化当前 chill → `chill-versions/v<时间戳>/`（排除 node_modules/dist-electron/target；target 为指向共享缓存 `chill-rust-target/` 的 junction，robocopy 默认遍历 junction 实化 1.5GB，必须排除）→ 校验快照 → 区分旧 chill 是 junction（仅删链接）还是真实目录（完整删）→ 重建 junction + 校正 current.json；**禁止手工复制粘贴 chill 目录**（会把 junction 变成真实目录、指针静默丢失）；若已复制粘贴导致断链，**双击 `chill-guardian/恢复指针.bat`**（freeze.js `--repair --build`：指针健康则不动，断链则固化修复+重建+构建）
- **删除操作一律走 switcher 内置的 `removeRecursive`（手工遍历 unlink/rmdir），禁用 `fs.rmSync`**：本机 Node 24 在含非 ASCII 字符的路径（如 `助手`）下 `fs.rmSync` 无论递归与否、文件或目录均静默失败（正常返回但不删除）；workcopy 清理、失败清理、`.backup-*` 清理共 6 处已全部替换，junction/符号链接子项只删链接不进目标（保护 pnpm workspace 链接指向的真实包目录）
- 自定位锚点：core `utils/projectPaths.ts` 的 `resolveProjectPaths()`，优先读环境变量 `CHILL_HOME`（由 switcher 的启动 bat 或 bootstrap 注入），否则向上查找 `pnpm-workspace.yaml` 并识别 `chill-versions/vX/` 模式反推 junction 路径；找到 workspace 但**不是 chill 项目**（缺 `.self.md` 或 `packages/cli`）或找不到时，返回 `projectPath: null`（npm 模式，自迭代功能全部优雅降级、self-iterate 技能被移除）

## npm 分发与自迭代引导（bootstrap + 指针）

- 运行环境分两档：**managed 布局**（开发机/workspace，projectPath 非空，功能完整）和 **npm 模式**（npm 安装，projectPath=null，仅 CLI 功能，自迭代命令提示 `/fetch-source`）
- CLI 以 npm 包 `@assistant-ai/chill-cli` 独立发布（`npm install -g @assistant-ai/chill-cli`，bin `chill`）：esbuild 三产物 `dist/bootstrap.js`（~2KB 薄启动器）、`dist/cli.js`（主 bundle，core 全量内联，无需 @assistant-ai/core 依赖）、`dist/workers/GenericSubagentWorker.js`（自包含 worker）；包内含 dist/templates、dist/skills（skill-creator 等内置技能可用，self-iterate 按 npm 模式过滤）、guardian/switcher.js；桌面 UI 以 electron-builder 安装包（nsis/dmg/AppImage）独立分发，安装包不含 CLI；两端共享 `~/.chill/`（API Key、模型、会话、记忆、Skill、MCP），一端建立的会话可在另一端继续
- bin 入口是 `dist/bootstrap.js`：读 `~/.chill/current.json`（`{active, home, updatedAt}`）——`active:"self"` 且 home 有效时委托运行 `~/.chill/workspace/chill/packages/cli/dist/cli.js`（注入 `CHILL_HOME`，版本不一致时打印漂移提示）；其余情况运行包内 `cli.js`
- `~/.chill/workspace/` 是 fetch-source 的源码落点，布局与开发机一致（chill/ + chill-guardian/ + chill-versions/ 等），自迭代机制在其中原样工作；switcher.js 由 cli 包随包携带（`guardian/switcher.js`，构建时从 `chill-guardian/` 复制）
- 指针指向 workspace 的 chill junction 路径，版本切换不换指针；`/use-npm`、`/use-self` 只改 `active` 字段

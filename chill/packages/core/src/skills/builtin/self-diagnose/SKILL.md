# Self-Diagnose · 代码自诊断

> 核心原则：**先 100% 确定原因，再下手从根本上解决。大多数失败的纠错都是因为主观假设而不是客观调查。**

本技能是通用的代码纠错/完善方法论，适用于任何代码项目。
边界说明：若诊断对象是 chill 助手项目自身的源代码，整体流程必须走 self-iterate 技能（workcopy/编译/测试/版本切换），本方法论在 self-iterate 流程的"修改代码"阶段内使用；需要添加调试代码观察运行时行为时，按下文"人机协作调试"执行。

## 诊断流程（七步）

### 第一步：逻辑链条分析（第一性原理）
先分析这个报错/待完善功能发生在哪些逻辑链条上：从输入/用户操作出发，到问题现象，中间经过哪些模块、函数、数据流。把链条完整列出来，不跳过任何环节。

### 第二步：了解代码现状
沿逻辑链条，用 read_file / search_content 阅读相关代码**原文**。
- 禁止依赖缓存记忆或印象作答；如果一个错误总是纠正不过来，更要丢掉记忆去读原文。

### 第三步：定位根本原因
- 不瞎猜、不武断：先详细检查代码，找到根本原因后再下手。
- 禁止打补丁/掩盖式修复（如在报错处随手包 try-catch 吞异常、加特判绕过）：要从顶层设计上、用最顺畅的思路解决。
- 若检查和推理不能确定根因：在与错误相关的**所有动作环节**添加带明显标记的调试代码（统一标记 `[DIAG]`，见下节），用输出说话，不要盲猜。
- 如有必要，设计专门的测试代码复现并定位问题。
- 若已确定原因，直接修改，不要画蛇添足地加调试代码或测试。
- 为消灭不确定，可搜索权威官方文档/资料求证。

### 第四步：规划修改步骤
列出修改清单：改哪些文件、每处怎么改、按什么顺序。

### 第五步：反省规划
带着规划重读一遍相关代码现状，评估是否会破坏其他无关功能；发现问题就更新规划，直到可以安全、准确地落地执行。

### 第六步：修改代码
严格按规划修改，不影响其他无关功能。

### 第七步：验证逻辑链条跑通
- 按修改后的代码完整走一遍逻辑链条，确认问题修复且无副作用。
- 如果错误总是纠正不过来：很可能在当前思路里陷得太深，**转换思路**重新从第一步开始。

## 调试代码生命周期管理（硬性规则）

1. **添加时必带统一标记**：所有临时调试代码必须带 `[DIAG]` 标记，例如：
   - `console.log('[DIAG] checkpoint-A: orderId=', orderId)`
   - `// [DIAG] 临时输出：验证缓存是否命中`
   目的：后续能用一次搜索（`search_content "[DIAG]"`）定位全部调试代码。
2. **修复确认后必须全部移除**：问题确认修复后，搜索 `[DIAG]` 标记，逐一移除所有调试代码，一处不留。
3. **移除时零误删**：
   - 只删带 `[DIAG]` 标记的调试代码本身（整行/整块）；
   - 删除前确认每一处确实是自己添加的调试点，不误删任何有用的既有代码；
   - 若调试代码与既有代码同行/交织，只剥离调试部分，保留原有逻辑原样。
4. **移除后闭环验证**：重新编译/测试，确认问题仍已修复、功能正常、无残留标记。

## 诊断 chill 自身代码时的人机协作调试

在 self-iterate 流程内诊断 chill 自身代码，需要添加调试代码并观察运行时行为时：

- **不需要用户配合**：优先自行编写测试脚本运行并获取输出，减少往返。
- **需要用户配合操作**（如问题只在交互操作中复现）：
  1. **先给用户关闭 auto-switch 的机会**：提示用户执行 `/auto-switch off`（已关闭则跳过），确保本轮迭代完成后打开体验窗口而不是自动切换版本，用户才有机会实际操作
  2. 在 workcopy 中添加带 `[DIAG]` 标记的调试代码 → 编译 → 打开体验窗口（用 `node "<chill-guardian绝对路径>\switcher.js" --preview "<chill项目绝对路径>"`——确定性启动器，CWD 由代码强制为项目父目录，不自行 Start-Process）
  3. 请用户在体验窗口中执行触发操作，把调试输出发回来
  4. 根据输出继续诊断（回到七步法的第三步）
  5. 修复确认后，按"调试代码生命周期管理"移除全部 `[DIAG]` 代码，再编译验证

## 反模式清单（不要做）

- 凭印象/缓存记忆描述代码行为，不读原文
- 在报错处打补丁掩盖症状，不追根因
- 修复时顺手"优化"无关代码（范围蔓延）
- 调试代码无标记、修复后遗留 console.log 等临时输出
- 移除调试代码时顺手删掉相邻的有用代码
- 需要用户配合调试时忘记先确认 auto-switch 已关闭，导致版本自动切换、用户失去操作窗口
